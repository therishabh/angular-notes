# Event Binding in Angular

## 1. Core Concept

**Event binding** allows Angular to listen for events from the DOM or Angular components and execute code in response.

Syntax:

```html
(event)="statement"
```

Example:

```ts
export class UserComponent {
  count = 0;

  increment() {
    this.count++;
  }
}
```

```html
<button (click)="increment()">
  Increment
</button>
```

The flow is:

```text
User action
    ↓
DOM event
    ↓
Angular event binding
    ↓
Component method
    ↓
Component state changes
```

So while **property binding** is:

```text
Component → View
```

**event binding** is:

```text
View → Component
```

---

## 2. How It Works

Angular uses parentheses to indicate an event:

```html
<button (click)="handleClick()">
```

Here:

```text
(click)        → event being listened to
handleClick()  → Angular expression executed when event occurs
```

Common events:

```html
(click)="onClick()"
<input (input)="onInput($event)">
<input (change)="onChange($event)">
<input (focus)="onFocus()">
<input (blur)="onBlur()">
<form (submit)="onSubmit()">
<div (mouseenter)="onMouseEnter()">
<div (mouseleave)="onMouseLeave()">
```

Angular listens for the event and evaluates the expression when it occurs.

---

## 3. Practical Example

### Basic Click Event

```ts
export class UserComponent {
  message = '';

  showMessage() {
    this.message = 'Button clicked';
  }
}
```

```html
<button (click)="showMessage()">
  Click Me
</button>

<p>{{ message }}</p>
```

When the button is clicked:

```text
click
  ↓
showMessage()
  ↓
message changes
  ↓
Angular updates the template
```

---

### Passing `$event`

Angular provides the event object through `$event`.

```html
<input (input)="handleInput($event)">
```

```ts
handleInput(event: Event) {
  const input = event.target as HTMLInputElement;
  console.log(input.value);
}
```

`$event` represents the actual DOM event.

For a click:

```html
<button (click)="handleClick($event)">
```

`$event` will be a `MouseEvent`.

For an input:

```html
<input (input)="handleInput($event)">
```

`$event` will be an `InputEvent`.

### Important

`$event` is an Angular template variable that gives you access to the event emitted by the target.

---

## 4. Important Points

### Event Binding vs Property Binding

These two are fundamental Angular concepts:

```html
<button [disabled]="isDisabled">
```

```text
Component → View
```

and:

```html
<button (click)="handleClick()">
```

```text
View → Component
```


## 5. Interview Questions

### Q1. What is event binding in Angular?

**Answer:**

> Event binding allows a component to listen for DOM or Angular component events and execute an expression when the event occurs. It uses parentheses: `(event)="expression"`.

---

### Q2. What does `(click)` mean?

```html
<button (click)="save()">
```

**Answer:**

Angular registers an event listener for the `click` event and executes `save()` when the event occurs.

---

### Q3. What is `$event`?

**Answer:**

`$event` is Angular's template reference to the event object generated by the event.

```html
<input (input)="handleInput($event)">
```

---

### Q4. Property binding vs event binding?

**Answer:**

| Property Binding          | Event Binding      |
| ------------------------- | ------------------ |
| `[property]`              | `(event)`          |
| Component → View          | View → Component   |
| Updates properties        | Responds to events |
| `[disabled]="isDisabled"` | `(click)="save()"` |

---

### Q5. What is the difference between DOM events and component outputs?

**Answer:**

A DOM event originates from an HTML element:

```html
<button (click)="save()">
```

A component output is a custom event emitted by an Angular component:

```html
<app-user (userDeleted)="deleteUser($event)">
```

---

### Q6. How can you listen specifically for Enter?

```html
<input (keyup.enter)="submit()">
```

Angular's event-key modifier lets you respond specifically to the Enter key.

---

### Must remember

* `()` = **event binding**
* `$event` = event object
* `(click)="save()"` = listen to DOM event
* `(userDeleted)="..."` = listen to component output
* `output()` = modern custom-event API
* `@Output()` + `EventEmitter` = older/common pattern
* Don't put complex business logic in templates
* Be careful with high-frequency events like `scroll`, `mousemove`, and `input`
* **Property binding = Component → View**
* **Event binding = View → Component**
